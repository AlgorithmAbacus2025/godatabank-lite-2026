# Proposed development roadmap

Status: draft planning, 27 November 2026; not an implementation authorisation and not a renumbering of earlier milestones.

| Stage | Work | Exit criteria |
| --- | --- | --- |
| Repository hygiene | Inventory, remove redundant placeholders, organise historical documentation | Reviewed diff; evidence and code unchanged |
| Baseline verification | Establish dependencies, tests, import paths, and deployment configuration | Repeatable test run and recorded limitations |
| Repository ownership | Decide private development authority and public deployment boundary | Deployment and history checked; no loss of unique material |
| Component classification | Map actual modules to engine contracts; separate deterministic tools from adaptive decisions | Reviewed responsibility and dependency map |
| Migration | Move reusable code and product code only after approval | Tests and imports pass; rollback documented |
| Agent integration | Evaluate bounded orchestration, model adapters, memory and tool permission controls | Measurable quality, cost, failure and approval criteria |
| Product integration | Research-to-verified-report workflow | End-to-end evidence traceability and publication gate |

No branch is designated canonical for future development by this document. No deletion of a repository, history rewrite, change of visibility, automatic publication or deployment migration is authorised here. Preserve the existing evidence chain and historical records until verified alternatives exist.
